# 从任务输入到交付验收

> 本文主轴：从收到写作任务，到材料准备、工具路由、成稿、复核和交付的完整流程。

## 适用范围

适用于需要交付给读者的文章、报告、发言稿、PPT 文字、内部沟通和结构化文档。短回复、说明和轻量修改可以直接完成，不必强行套完整流程；篇幅较长、信息多或成品格式要求严格的任务，按阶段推进。

本流程描述的是**可裁剪的工作流**，不是每次都必须调用同一组工具。内容真实性、用户给出的约束和读者需要优先于任何风格指标。

## 流程

### 1. 收集任务简报

开始前确认：

- 写作目的和读者；
- 文体、交付格式与篇幅；
- 必须保留的事实、观点、名称、时间和数字；
- 不应出现的内容及可用材料范围；
- 是否要匹配某种文风，以及用户是否提供了可用的参考样本。

关键背景缺失、不同要求互相冲突，或可能影响事实和交付的决定尚未确定时，先向用户追问。非关键细节可采用保守默认，并把假设说清楚。

### 2. 判定材料状态与使用边界

区分“已有材料可整理”和“还需要补充信息”两种情况。检查材料来源、可引用范围、敏感信息和授权边界；私人原稿和消息只在用户授权的本地任务中使用，不复制到方法库，也不把私人样本当作可公开示例。

事实材料要记录出处。没有来源支持的观点应标作待核实，不能为使文章完整而补造事实、引用或数据。

### 3. 识别任务类型并选路线

- **短回复、说明或轻量润色**：直接完成，只做与任务规模相称的检查。
- **长文且缺少素材**：先访谈、收集想法和事实，再整理结构；当前实践中预计超过 1500 字通常进入长文路线，这个阈值可按项目调整。
- **长文且已有素材**：先筛选、分类和核验素材，再逐步收敛结构并成稿。
- **需要边探索边选择方向**：使用分步选择方向的路线，不预先锁死完整结构。
- **只需改现有文章结构或段落**：按标题和信息依赖分节处理，不把整篇推倒重写。
- **结构化文档或特定沟通文体**：按对应流程分阶段协作，必要时加载该文体的规范。

### 4. 按文体选择工具与文风目标

命中已安装且适用的 Skill 时，按它的职责执行；同一任务可以串接多个专门环节，但要说明每个环节的输入、输出和交接。不同 Skills 的依次分工或独立复核，不等于严格统计意义上的 bagging；不要用“投票”掩盖冲突，最后由负责整合的人依据事实、用户约束和文体要求作判断。

如果 Skill 未安装或不能调用，不声称已经调用；说明限制后，按相同职责手动完成，或者询问用户是否要暂停。

文风只按任务需要启用。长文、群通知和群聊等不同场景不能共用一套目标带；定量画像的取样、指标与解释见[文风定量画像](03-style-measurement.md)，具体 Skill 的组合与来源见[Skills 编排](02-skill-orchestration.md)。

### 5. 选择起稿方式并按规模协作

长文没有现成材料时，先用访谈补足经历、事实和判断，再逐步收敛结构；有材料时先整理材料，不急着铺完整大纲。**这是长文路线，不是一条适用于所有文体的禁令**：结构化文档要先约定交付结构，PPT 和发言稿则按页面逻辑、演讲场景安排顺序。若任务需要读者在多个可能方向间逐步作选择，则使用探索式路线。

长文、提案等高信息量任务按阶段或章节起草、确认，再继续下一部分。短文、简单修改不必逐段确认，可以先给完整初稿。任何时候都不默默丢掉用户要求保留的内容；确需删减时说明理由和去向。

### 6. 先审报告，再决定怎么改

自动风格检查、AI 文风检查或其他分析工具的结果是**候选问题**，不是自动改稿授权。先解释问题、证据和建议；只对用户确认或已明确授权的项目修改。修改后重新运行相应检查，并通读全文，避免只修被标记的句子却引入新的不一致。

### 7. 核验事实、完整性与格式成品

交付前分开检查：

1. **事实与来源**：人名、数字、日期、引文和可验证陈述是否准确、可追溯；
2. **内容完整性**：是否符合用户明确要求，有没有漏项、静默删减或未经同意新增；
3. **文风与文体**：是否符合受众、场景和本次选定的目标；指标只作参考，不能压过意思；
4. **成品格式**：Word、PPT 等交付格式要检查实际导出的成品。需渲染时查看真实页图，不能只看源文本、代码或生成脚本报告。详细验收规则见[修订与交付验收](04-revision-and-acceptance.md)。

根据风险和文体选用适当项目，不因清单存在就对所有短回复做一遍重型验收。

### 8. 交付并沉淀可迁移经验

交付时说明完成了什么、删改了什么及其去向、还有什么未解决。用户反馈中可复用的规则，经确认后再提炼成通用方法；原始聊天、个人原稿、真实风格数值和含身份信息的实例留在私有语料层，不放进方法库。

方法是否有效以及怎样比较不同工作流，见[方法效果评估](05-evaluation.md)。

## 交付前检查

按文体和风险选择验收项。最低限度确认事实和约束准确、内容没有静默丢失；Word/PPT 等成品还要检查真实导出效果。细则见[修订与交付验收](04-revision-and-acceptance.md)。
