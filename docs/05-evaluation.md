# 方法效果评估

## 评估问题

先说清要验证哪一部分：任务路由、素材整理、Skill 组合、风格检查、修改建议，还是最终成稿。不要把“使用了更多 Skills”直接当成质量提高；比较对象应是明确的工作流或处理步骤。

## 对照设计

比较两种流程时，尽量固定任务简报、事实材料、读者、文体、篇幅和交付格式，只改变要考察的那一项。可设置未使用该步骤的基线流程与候选流程；如比较多个阶段，应逐个改变，避免把多个变化的效果混在一起。

用于真实评估的材料必须经作者授权并保存在私有环境。公开方法库只描述实验设计，不放原文、个人语料、真实统计量或评分结果。需要演示操作时用明确标注的虚构材料；虚构结果不能写成实测结论。

## 评审与指标

尽可能隐藏文本由哪种流程生成、随机调整展示顺序，减少评审者对工具名称或先后顺序的偏见。按任务设定少量可观察维度，例如：

- 事实、引文和数字是否准确；
- 必须保留的内容是否完整，是否出现未经授权的新增；
- 是否符合文体、受众、语气和交付格式；
- 表达是否清楚，是否保留作者认可的声音；
- 风格量化指标是否接近该场景的目标范围。

人工评价与机器指标分开记录。先报告各项判定和分歧，不急着合成一个总分；若要加权，先说明权重依据，并做敏感性检查。打分不应把内容正确性、可读性和风格相似度混成同一个概念。

### 评分锚点与评审者

评审前固定评分量表，为每个维度写清各档含义（例如“不满足/部分满足/满足”），并记录量表版本和评审者人数。需要多人判断时，先独立评分，再记录分歧如何处理。准确性和硬性约束可设为单独门槛，不能被其他维度的高分抵消。

## 报告与限制

记录任务简报版本、比较的流程步骤、所用工具及版本、评审方式、指标口径、异常和限制。公布时只分享方法、空白记录模板和虚构示例；私有文本、真实数量和个人得分留在本地。

结论只覆盖实际测试的文体、材料和工具版本。样本少、评审者少或评分不一致时，说明不确定性，不把一次结果推广成普遍规律。没有实际测过的部分就标“未验证”，不填造成功率、评分或引用。

## 空白评估记录模板

```text
评估问题：
任务简报（脱敏摘要）：
基线流程：
候选流程：
唯一改变的环节：
评审者人数：
评分量表/锚点版本：
评审方式与盲法：
预先确定的评价维度：
观察结果（未测时留空）：
分歧与异常：
适用范围与限制：
数据保管说明（只写本地/受控环境；共享副本不含具体路径）：
```

模板只用于记录真实试验；没有执行的试验保持空白，不用随机数填作结果。随机数只可用于讲解算法，必须明确标成虚构示意。
